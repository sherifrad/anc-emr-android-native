Covers ui/report/PatientTwoPageReportDialog.kt (Level 3), ui/report/ReportSections.kt, and strings.xml. Static design specification mockup. Protected files ui/report/PatientPrintHtmlGenerator.kt, ui/report/PatientPrintManager.kt, and ui/report/PatientShareText.kt are untouched. Real sample data: Mona Ragab / منى رجب (27+2 wks, G4 P1 A2, BP 110/70, A+, EDD 11/02/2027, Mothercare; fees 12000 excluded from delivery plan per deliveryPlanRows), supplemented where absent by clearly labeled in-repo DemoFixtures records (DEMO-ANC-001, DEMO-ANC-002, DEMO-ANC-004) and bracketed placeholders.

Design reasoning

Reading this as: a bedside clinical record summary dialog where doctors review Page 1 and Page 2 on a 360 dp phone, switch cleanly between pages, share plain-text summaries, and trigger A4 PDF printing without horizontal table scroll or dark-mode glare. Antislop dials: ENERGY 1 / RHYTHM 1 / MOTION 1 (pressed and focus states only, no new animation).

  • Native Record-system Page 1 and Page 2 replace the cramped WebView sheet on screen: today reportWebView embeds light-only 7.5 pt HTML inside 600 px tables that force sideways scrolling on 360 dp phones and stay blinding white in Dark Theme. Rendering the exact same ReportSections data in native Compose cards adapts to Dark Theme, respects fontScale 1.3, eliminates horizontal table scroll, and leaves PatientPrintHtmlGenerator.kt intact for Print PDF.
  • Calm high-contrast header with full-width RTL-safe patient name: move the dialog chrome from a shadowed navy slab with a 2.83:1 rose pill and 11 sp ellipsized name onto a flat surface header (0 dp elevation, 48 dp Close/Share/Print PDF buttons, primary/onPrimary 10 dp Print button), giving PatientNameText full width so Arabic names like منى رجب anchor right and long English names wrap without colliding.
  • Two-page switcher with 48 dp RecordFilterChips: replace endless two-sheet scrolling with explicit Page 1 (identity, dating, histories, previous pregnancies, visits) and Page 2 (scans, labs, medications, delivery plan, clinician attestation) chips that stay unclipped side-by-side at 1.3x scale.
  • Domain family rhythm without box-inside-box clutter: Patient blue for identity, dating, and visits; Obstetric teal for previous pregnancies and scans; Background sand for histories, labs, and medications; Delivery plum for delivery plan. Multi-item logs (previous pregnancies, visits, scans, labs, medications) use hairline-separated rows with PlainField, BandChip, and StatusWord inside one RecordSectionCard per section.
  • Print crash boundary respected: the known PrintManager Activity context defect lives outside Slice 20; printReportButton keeps its exact PatientPrintManager.printPatientReport(...) call unchanged.

9. Decisions for the owner (max 5)

  1. Native Compose Page 1 & Page 2 body vs keeping AndroidView(WebView) (reportWebView tag): Today the dialog mounts only a light-mode WebView with 600 px tables. Grep confirms zero tests in androidTest or test reference reportWebView. Recommend: render Page 1 and Page 2 natively in Compose (Page 1 and Page 2 switcher) and retire reportWebView from the dialog (keeping PatientPrintHtmlGenerator untouched for Print PDF); alternatively, keep reportWebView behind an optional 3rd Print sheet chip if on-screen A4 inspection is wanted.
  2. Gestational age format in the native report cards (27+2 wks vs 27w 2d): PLAN.md Decision 9 sets 27+2 wks across reports, whereas reportGestationalAge() in ReportSections.kt returns 27w 2d (pinned by ReportSectionsTest) and scanGestationalAge() returns 12w + 3d. Recommend: leave reportGestationalAge() and scanGestationalAge() untouched for tests, print HTML, and share text, and display shortWeeksText (27+2 wks) for current/visit GA in the native dialog cards.
  3. Sentence-case section headings in native UI vs HTML Title Case: PatientPrintHtmlGenerator.kt uses Title Case headings and ALL-CAPS CLINICAL RECORD / CONTINUED badges. Recommend: keep every clinical value, ReportRow.label (Delivery Outcome, Planned delivery, Hospital, Postpartum, Blood bank precautions, Estimated due date, Plan), and ReportRisk label (Medium risk, High risk, Low risk, Risk not recorded) verbatim, while using sentence case for native section headings and Clinical record / Continued chips.
  4. Clinician attestation block on Page 2 without dashed Stamp box: Print HTML ends Page 2 with Dr. Sherif Radwan / Arabic signature and a dashed Stamp placeholder. Recommend: render the clinician attestation card on Page 2 without the empty physical Stamp box (which stays in A4 print HTML only).
  5. Known PrintManager Activity context crash: Recommend: keep PatientPrintManager.printPatientReport(context, patient, securitySettings) verbatim inside printReportButton and leave the Activity context fix in its dedicated separate task.
