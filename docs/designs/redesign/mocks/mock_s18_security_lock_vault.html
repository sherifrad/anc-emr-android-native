Mock S18: Security, lock and vault

Covers ui/SecuritySettingsDialog.kt, ui/AppLockScreen.kt, and ui/VaultGateScreen.kt (Level 3: auth and security). Presentation only: PIN validation, PBKDF2 hashing, lockout timers, biometric prompt, encrypted backup/restore, and vault state transitions remain identical. Every string comes from strings.xml or existing code, with zero invented security claims.

Design reasoning

Reading this as: clinical security settings, PIN entry, and encrypted vault access where clinicians switch tabs without clipping, read errors clearly, and avoid accidental destructive actions on a 360 dp phone. Antislop dials: ENERGY 1 / RHYTHM 1 / MOTION 1 (pressed and focus states only, no new animation).

  • Patient (slate-blue) family for app identity and security: use FieldFamilies.patient() (#E9EEF8 / #23407A light, #22304A / #AFC6F2 dark) on the Security and clinic tab, PIN/backup dialogs, AppLockScreen, and VaultGateScreen, keeping FieldFamilies.background() sand distinct for the Lab tests and Medications catalog tabs.
  • Unclipped settings tabs inside 306 dp dialog width: replace the 3-column PrimaryTabRow that clips "Security & Clinic" with a wrapping FlowRow of 48 dp RecordFilterChips (Security & clinic, Lab tests, Medications), matching Slice 17's switcher inside the same dialog.
  • Calm RecordSectionCards and unclipped 48 dp backup actions: replace shadowed 20 dp/14 dp grey slabs with flat 16 dp outlined cards, drop decorative section/button icons and `#FBF8F5` emblem developer jargon, and give Export backup and Restore backup 48 dp 10 dp buttons (stacking above 1.3x font scale).
  • Scrollable FormDialogs and error-colored destructive restore: move PIN change, backup export, and restore passphrase dialogs onto 16 dp white surfaces with external 12 sp labels and pinned SheetCancelSaveRow footers; add a title to restore_confirm_dialog and color Replace all in error so it no longer looks like the safe default.
  • 3:1 contrast on AppLockScreen and unmistakable Blocked vault state: change empty PIN dot and keypad button borders from outlineVariant (1.61:1) to outline (4.30:1 light / 6.24:1 dark), use flexible error height (fixing multi-line clipping at 1.3x+), show disabled keys honestly during lockout, and mark VaultState.Blocked with a StatusHigh header band and BandChip.

9. Decisions for the owner (this slice)

  1. Settings tab bar pattern and label (FlowRow of RecordFilterChips vs SecondaryScrollableTabRow): Recommended: use a wrapping FlowRow of 48 dp RecordFilterChips labeled "Security & clinic", "Lab tests", and "Medications" so every tab stays visible at once and never clips at 1.3x or 2.0x scale.
  2. Domain color family (FieldFamilies.patient() blue vs neutral / sand): Recommended: use FieldFamilies.patient() slate-blue across Security & clinic, PIN/backup dialogs, AppLockScreen, and VaultGateScreen to separate app security and clinic identity from the sand catalog tabs.
  3. Destructive restore confirmation (restore_confirm_dialog): Recommended: add heading "Replace all patient records?" and style "Replace all" in MaterialTheme.colorScheme.error inside a 48 dp TextButton, matching DiscardChangesDialog and CatalogConfirmDialog.
  4. Dual biometric trigger on AppLockScreen (pinKey-biometric + useBiometricButton): Recommended: preserve both under the exact existing condition so zero Level-3 behavior or testTags change, while replacing the disabled grey alpha box on pinKey-biometric with a crisp outlineVariant disabled state.
  5. String normalization and developer-jargon removal: Recommended: move hardcoded UI text into strings.xml in sentence case, keep the 4 test-asserted strings ("Clinic & System Settings", "Auto-Lock Timeout", "Locks after 10 minutes away.", "Incorrect PIN. Please try again.") verbatim, replace the #FBF8F5 emblem implementation note with "Shown on the home screen, lock screen, and printed reports.", and default VaultGateScreen branding via R.string.app_name and R.string.clinic_default_subtitle.
