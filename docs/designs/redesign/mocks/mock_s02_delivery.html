Mock S02: Delivery planning card and delivered state

For slice 2. Builds on mock D and the slice 0 components as built (RecordSectionCard, LabeledValue, StatusTag). Sample data: Mothercare, 12000 for Mona Ragab. The sample has no delivery, so the delivered frames show what the app prints today for a delivered flag with no date ("???"), and one layout-only frame uses bracketed placeholders.

Design reasoning

Reading this as: the Overview and Plan tab delivery card for doctors, calm Material 3 clinical, dial ENERGY 1 / RHYTHM 1 / MOTION 1.

  • One family, not four hues. Today's card uses purple, green, blue and pink boxes with uppercase titles. It becomes a RecordSectionCard in the Delivery family (plum tint #EEE9F5, label #4E3A78), the same pattern as every other Overview section.
  • Labels in sentence case through new display strings. The existing delivery_*_title strings stay exactly as they are: model/DeliveryNotes.kt parses notes with "Agreed Delivery Hospital:" and the plan sheet uses them as field labels.
  • All four fields full width. Hospital names and fee text are free text, and "Agreed delivery hospital" wrapped at half width in mock D's own check.
  • Missing value reads "Not recorded" (the shared LabeledValue default) instead of "No record". One wording across the record.
  • Delivered state. A StatusTag "Delivered" and a "Delivery date" field lead the card; mode and outcome follow as fields when recorded, hidden when not (today's rule). The unknown date keeps the owner's "???" convention, which a test asserts.
  • Dropped: the calendar icon before the title, the pencil icon (replaced by the word "Edit", 48 dp), the tinted card background, the one-line "Delivered, date ??? · 3 days ago" headline with a middle dot.

  1. DeliveryPlanningCard: RecordSectionCard(title = stringResource(R.string.delivery_planning_title), family = FieldFamilies.delivery(), modifier = modifier.testTag("deliveryPlanningCard"), action = if (canEdit) { { SectionTextAction(stringResource(R.string.action_edit), stringResource(R.string.edit_delivery_plan), onEditDeliveryPlan, Modifier.testTag("editDeliveryPlan")) } } else null).
  2. Four LabeledValue(label, value) full width, no stretch, each with its existing tag on the modifier: deliveryHospital, deliveryFees, deliveryPlan, deliveryPostpartum. Values from parseDeliveryNotes unchanged; null shows "Not recorded".
  3. DeliveredSummary (tag deliveredSummary on a Column(spacedBy(12.dp))): StatusTag(StatusKind.Delivered); LabeledValue(R.string.delivery_date_label, dateText, emphasis = true, modifier = Modifier.testTag("deliveredHeadline")); then, when present, a LabeledValueRow with mode (deliveredMode) and outcome (deliveredResult), stretch = true, Modifier.weight(1f).fillMaxHeight(). If only one exists it is full width.
  4. dateText: known date: "dd MMM yyyy" (same formatter as deliveredHeadline) plus ", " + deliveredDaysAgo(...) when not null; unknown date: "???" from a new string delivery_date_unknown_value, shown in the missing style (pass it as value = null, missingText = ...).
  5. Dark mode comes from FieldFamilies.delivery() and StatusTag; nothing hard-coded.
