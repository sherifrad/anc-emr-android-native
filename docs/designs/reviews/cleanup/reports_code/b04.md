## Findings

### Major

**1. Decorative separator banners throughout `VisitEntryLogic.kt`** — rule: "Decorative Separators" (R-31).

The file repeats this pattern 8 times, each a two-line dash banner wrapped around a section label:

```
// -------------------------------------------------------------
// Blood Pressure Flagging
// -------------------------------------------------------------
```

Instances appear before:
- `Blood Pressure Flagging`
- `Structured Form Values & Normal Fill Rules`
- `"Same as Last" Historical Extraction`
- `"Matches GA" Estimation for Fundal Height`
- `Findings Serialization & Round-Trip Parsing`
- `Clinical Assessment & Safety Helpers`
- `Flagged Findings Detector`
- `Summary Formatter Matching Mock`

**Quoted:** `// -------------------------------------------------------------`
**Rule broken:** banner comments built from repeated characters are decorative slop — "the decoration is the message."
**Fix:** for each of the 8 banners, keep at most a single plain line if the label carries information (e.g. `// Legacy narrative fallbacks for old free-text findings`), and delete both dash lines. Several of these labels also add nothing (`Summary Formatter Matching Mock` names neither a fact nor a constraint) — delete those entirely.

**2. Em dash in user-visible text — `VisitEntryLogic.kt`, `formatVisitSummary()`**

**Quoted:**
```kotlin
parts.add("BP $s/—")
...
parts.add("BP —/$d")
```
**Rule broken:** em dash character in user-visible text (the returned summary string is rendered to the clinician in the visit summary row). This is not a placeholder convention in the codebase — it leaks a typographic dash into the "BP 120/—" string a user reads.
**Fix:** use the ASCII hyphen: `"BP $s/-"` and `"BP -/$d"` (or omit the half-read BP entirely when one component is missing — a summary reading `BP 120/-` invites misreading the diastolic as zero).

### Minor

**3. Loud wording in the clinical invariant doc — `VisitEntryLogic.kt`, above `fillNormalVisitFindings()`**

**Quoted:** `* CLINICAL SAFETY INVARIANT:` / `* Strictly NEVER modifies blood pressure, weight, fundal height, date, or notes.`
**Rule broken:** "Stiff or Loud Wording" — the ALL-CAPS label and "Strictly NEVER" shout. The content itself is exactly the kind of comment the skill says to preserve (a safety constraint the code does not show), so this is wording only.
**Fix:** keep the invariant, drop the shouting, e.g.:
```kotlin
// Safety invariant: only fills blank findings below; never touches BP,
// weight, fundal height, date, or notes.
```
One or two lines, same facts.

**4. Vague label — `VisitEntryLogic.kt`, "Summary Formatter Matching Mock"**

**Quoted:** `// Summary Formatter Matching Mock`
**Rule broken:** "Empty Labels" / "Vague Placeholders" — "Matching Mock" points at an unspecified mock; a reader can't act on it.
**Fix:** either delete (the function name `formatVisitSummary` already says what it does) or state the actual fact, e.g. `// Field order mirrors the Figma visit-summary mock`.

### No finding

- `// Split strictly by canonical joiner " · " to avoid breaking commas in free text` — earns its place (explains a non-obvious parsing constraint).
- The two-line comment above the legacy-narrative fallback scan — earns its place and stays within the length rule.
- `VisitVitals.kt` contains no comments; nothing to flag there.

**Summary:** 2 major (banner separators ×8 as one defect; em dash in the rendered BP string), 2 minor (loud invariant wording, vague "Matching Mock" label).
