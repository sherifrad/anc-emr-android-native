# Print v2 build plan (owner approved mock B3 on 2026-11-18; PatientPrintHtmlGenerator.kt edit approved)
Mock: docs/designs/mocks/export_v2/mock_b3.html (PDF mock_b3.pdf). Owner changes to B: scan outcome column, unlinked scans table, grouped lab comparison, medications compact two columns, pictures page with figure references, owner selects which pictures print.
Rule: ONE data layer decides what is shown (reuse, no copies). The print HTML, the native report and the share text all read it.
## Slices
S1 data layer (new file ui/report/ReportData.kt, pure Kotlin, no Android): scan outcome per visit, unlinked scans, lab comparison groups, picture candidates and figure numbering. Unit tests.
S2 print HTML (ui/report/PatientPrintHtmlGenerator.kt, protected, approved): render B3 from the data layer; medications two-column; flow layout (no fixed page sheets), images page only when figures exist; fixed footer; no page numbers.
S3 native report (ui/report/ReportSections.kt, PatientTwoPageReportDialog.kt): same content from the data layer; whole-page scaled preview (no sideways scrolling).
S4 picture selection before print (report dialog): list of candidate pictures with thumbnails and checkboxes, selection kept for the dialog, embed selected pictures in the HTML as downscaled data URIs.
S5 share: Share PDF and Share text (short). Separate step.
## Data rules (S1)
- Scan for a visit: the LATEST scan with scan.linkedVisitId == visit.id or visit.linkedUltrasoundId == scan.id (by date, then id). Unlinked scans: all others, oldest first.
- Scan outcome text: pregnancy type from fetalNumber (Singleton; Twins -> "Multiple pregnancy: twins"; Higher order -> "Multiple pregnancy: higher order"; null -> omit), presentation (as stored), measurements as label and value pairs for non blank BPD, HC, AC, FL, EFW (EFW keeps its unit as stored or g). An optional third line only when present: amniotic fluid when not Normal, placental site, fetal heart rate, impression text (so nothing the old table printed is lost).
- Labs: a test is repeated when it has results on 2 or more distinct dates. Repeated tests are grouped by testCategory into comparison groups: rows = test names (unit in the row label), columns = distinct dates oldest to newest, at most 6 date columns per table (more dates continue in a following table of the same group). Tests with one date are listed individually (test, date, result and unit). Flag: use isAbnormal and labResultFlag(result, referenceRange) for H or L; abnormal without direction shows an asterisk. No reference ranges are printed.
- Pictures: candidates = scan.imageUris + patient.attachments (linkedRecordId can be a scan id, visit id or null = patient profile). Each candidate: stable key, source label (Ultrasound dd/MM/yyyy, Visit #n, Patient profile or attachment title), date, linked record id, the raw location (uri or file name). Figure numbers are given only to SELECTED candidates, in date order; scan and visit rows get "Fig N" references from their selected pictures.
