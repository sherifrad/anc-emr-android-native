# F2 redesign (owner request 2026-11-14, replaces section F2 of SPEC.md): Clinical attention as structured entries

Owner decisions: several entries per patient, each with its own level chosen from a dropdown (Critical, Alert, Note) and its own text; stored in the EXISTING `clinicalAttention` string (no schema change, no protected storage file touched); a compact strip in the patient header plus a dedicated card in the Overview tab; no quick-phrase chips in this version; the severe blood pressure alert stays automatic and cannot be deleted.

## Storage format (inside the existing String)
One entry per line, written as `LEVEL: text` with LEVEL in CRITICAL, ALERT, NOTE (upper case, one space after the colon). Reading is tolerant for data written by the old dialog: accepted prefixes (case-insensitive) `CRITICAL:`, `[CRITICAL]`, `ALERT:`, `[ALERT]`, `WARNING:`, `[WARNING]`, `NOTE:`, `[NOTE]` (WARNING means ALERT). A leading bullet `•` or `-` on a line is stripped. A line WITHOUT a prefix inherits the level of the previous line's entry (the old dialog put one prefix on a whole multi-line text); if it is the first line its level is ALERT (free text in an attention field is attention-worthy, never silently "safe").

## New file `ui/patienthub/components/ClinicalAttentionEntries.kt` (pure Kotlin, no Compose)
```kotlin
data class AttentionEntry(val level: ClinicalAttentionLevel, val text: String)
const val ATTENTION_TEXT_MAX = 140
const val ATTENTION_ENTRIES_MAX = 10
fun parseAttentionEntries(raw: String?): List<AttentionEntry>      // as above, blank lines skipped, text trimmed, never throws
fun composeAttentionEntries(entries: List<AttentionEntry>): String // "CRITICAL: a\nNOTE: b"; blank-text entries dropped; text cut to ATTENTION_TEXT_MAX; at most ATTENTION_ENTRIES_MAX entries kept; "" when nothing remains
fun sortedForDisplay(entries: List<AttentionEntry>): List<AttentionEntry>   // CRITICAL first, then ALERT, then NOTE; stable inside a level
fun clinicalAttentionLevel(attention: String?, severeBp: SevereBpAttention?): ClinicalAttentionLevel
```
`clinicalAttentionLevel` = CRITICAL when severeBp != null; otherwise the highest level among `parseAttentionEntries(attention)`; NOTE when there are no entries. `ClinicalAttentionLevel.parse` (existing, in ClinicalAttentionBanner.kt) may stay for the old banner composable but the strip, card and dialog must use the functions above. Round trip: `composeAttentionEntries(parseAttentionEntries(x))` is stable (applying it twice gives the same string). Examples: "[ALERT] Mild anemia\n• Calcium missed" gives two ALERT entries; "NOTE: Prefers female doctor\nCRITICAL: Severe PIH" gives [NOTE, CRITICAL] and `sortedForDisplay` gives [CRITICAL, NOTE].

## Colours (one shared helper, used by strip, card, dialog and the old banner)
`@Composable fun attentionColors(level): AttentionColors(container, content, accent, border)` in ClinicalAttentionBanner.kt. CRITICAL: `errorContainer` / `onErrorContainer`, accent `error`, 1.5 dp border. ALERT: `ClinicalCardTokens.WarningBg / WarningText / WarningAccent / WarningBorder` (dark: the WarningDark* tokens). NOTE: `surfaceContainerHigh` / `onSurface`, accent `outline`. No tertiary and no primary colour anywhere in attention UI. Level is never shown by colour alone: every entry carries the written level word ("Critical", "Alert", "Note", string resources) and an icon (Warning for Critical and Alert, Info for Note; icons `aria-hidden` equivalent: contentDescription null, the word is the label).

## Header strip (`PatientHubHeader.kt`, `CompactClinicalAttentionStrip`)
Hidden when there are no entries and no severe BP. Otherwise one tappable surface (tag `clinicalAttentionStrip`, also `clinicalAttentionBanner`, min height 48 dp) coloured with the HIGHEST level, showing on one line the severe BP text first when present ("Severe BP: 165/105 (date)") then the first entry of the highest level, and "+N" (N = remaining entries, string resource) when more exist; text ellipsised at one line; tapping opens the editor dialog (existing `onOpenDialog`).

## Overview card (new file `ui/patienthub/components/ClinicalAttentionCard.kt`, `ClinicalAttentionCard(attention: String?, severeBp: SevereBpAttention?, onEdit: (() -> Unit)?, modifier)`; tag `clinicalAttentionCard`)
A card in the same style as the other Overview group sections (use `ClinicalGroupSection`, title "Clinical attention", the pencil action tag `editClinicalAttention` when `onEdit != null`). Body: the automatic severe BP entry first (Critical, cannot be edited here), then `sortedForDisplay(parse...)`, one row per entry (tag `attentionEntry-<index>`) with the level word, the icon and the text wrapped (no ellipsis), coloured by `attentionColors`. Empty state when there are no entries and no severe BP: the text "No clinical attention recorded" and, when `onEdit != null`, a button "Add attention" (tag `addClinicalAttention`, 48 dp). The card is hidden only when it is empty and `onEdit == null`. `OverviewTab` gets a new parameter `onEditAttention: (() -> Unit)? = null` (default keeps old callers) and shows the card at the TOP of the tab; `PatientHubScreen` passes `onEditAttention = { showAttentionDialog = true }` when the patient can be edited.

## Editor dialog (`ClinicalAttentionDialog(currentAttention: String, onDismiss, onSave: (String) -> Unit)`, same signature as today, rewritten)
Content: (1) the existing entries, one row each: a level dropdown (tag `attentionLevel-<index>`), a text field (tag `attentionText-<index>`, single paragraph, counter "n/140"), a delete icon button (tag `attentionDelete-<index>`, 48 dp, content description "Delete entry"). (2) A new-entry row at the bottom: level dropdown (tag `attentionNewLevel`, default Alert), text field (tag `attentionNewText`, label "What should the next doctor know?"), "Add" button (tag `attentionAdd`, 48 dp, enabled only when the text is not blank and fewer than 10 entries exist). Pressing Add appends the entry to the list above and clears the new text field. Level dropdown: a button showing the level word and a small drop-down arrow that opens a `DropdownMenu` with three items "Critical", "Alert", "Note" (each with its icon; tags `attentionLevelOption-critical|alert|note`). Save (tag `attentionSave`, label from `R.string.save`) calls `onSave(composeAttentionEntries(entries))` after also adding any non-blank text still waiting in the new-entry field; Cancel dismisses with no change. Text in the dialog is not cut off at 360 dp (fields wrap). The old dialog's three level buttons and its single multi-line text area are removed (one canonical editor).
Save path stays the existing one in `PatientHubScreen` (it starts the patient editor, sets `PatientDraftField.CLINICAL_ATTENTION` to the string and submits); an empty string clears the attention.
