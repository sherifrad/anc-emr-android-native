# Brief: edit the delivery plan in place on the Plan tab

Repository: Android antenatal-care EMR (Kotlin, Jetpack Compose, MVI: AncState, AncEvent, AncReducer, AncViewModel). Room schema v6 is frozen: no new column, no migration. The Meds tab was just changed so that add, stop and edit happen in a bottom sheet on the same tab with no navigation (MedicationSheet and MedicationForm under ui/patienthub/components; the sheet is hosted in PatientHubScreen; the draft is a state slice; starting a draft does not change the route). This brief asks for the same treatment for the delivery plan.

## The problem
On the Plan tab the Delivery Planning card has a pencil button (tag editDeliveryPlan, file ui/patienthub/components/DeliveryPlanningCard.kt). It sends AncEvent.StartPatientEditor, whose reducer (startPatientEditor in state/ClinicalDraftReducers.kt) sets the route to AncRoute.PatientEditor and shows the full-screen patient profile form (ui/PatientEditor.kt, 638 lines). That replaces the Plan tab (the same route swap that made the Meds tab reload) and shows the whole profile form where the only relevant field is one free-text box, "Obstetric notes" (PatientDraftField.OBSTETRIC_NOTES, tag patientObstetricNotes).

## How the delivery plan is stored
There is no structured delivery data. The card shows four boxes ("Agreed Delivery Hospital", "Agreed Delivery Fees", "Delivery Plan", "Postpartum Note"). They come from parseDeliveryNotes(notes) in ui/DeliveryNotesParser.kt, a pure heuristic classifier over the single free-text obstetricNotes string. Facts about the parser: it splits each line into segments at ';' and at sentence ends, places each segment in exactly one of fees, plan or postpartum (plan is the fallback, nothing is ever dropped), and additionally lists hospital names found in "<Name> Hospital" phrases or a "Hospital: <name>" value (a hospital line also stays in its home section). Only these label prefixes before ':' are recognised and stripped: "hospital", "plan", "postpartum" or "postpartum note", and "fee"/"fees"/"delivery fee(s)" optionally followed by package, agreed, quoted, discussed, proposed or estimate. A fee segment containing quoted, estimate, proposed, discussed, undecided or "not agreed" is placed in plan, not fees. The clinical summary and print generators also read obstetricNotes.

## The work to design
Replace the pencil's navigation with a bottom sheet over the Plan tab that edits the four boxes in place and saves back, with no route change and no new schema.

Constraints: AGENTS.md rules (one canonical component per clinical entity, no UI file over 1,500 lines, 360 dp first with nothing critical truncated, unidirectional MVI, no legacy shims, no dead code, files under ui/patienthub/components for shared pieces). Reuse the existing patient draft and the existing profile save command (SubmitPatientProfile, UpdatePatientCommand path) rather than a new command if that works. Level-3 files (state/, storage/, PatientHubScreen.kt) need an independent review.

## Decisions the design must make and justify
1. The write-back. Because storage is one text field, the sheet must compose the four boxes back into obstetricNotes. Propose the exact compose rule (for example one labelled line per non-empty box using labels the parser recognises) and PROVE the round trip: parse(compose(sections)) must give the same four sections for any sections the parser could produce. State what happens to a hospital list and to text that the parser placed in a box by heuristic. State the user-visible consequence: the first Plan edit rewrites the patient's existing notes text into labelled lines; say how the sheet tells the doctor, and how the patient form, the print and the clinical summary will then read it.
2. State: how the sheet opens and closes without changing the route, which draft it uses (reuse patientDraft or a small delivery draft), dirty and discard rules (touched flag like the medication sheet), what happens if another draft is open or a save is running, archived patients, and recovery after a crash.
3. UI: fields, labels, 360 dp layout, keyboard behaviour (focused field visible), Save and Cancel, failed-save message (reuse the existing SaveUiError messages), disabled controls while saving, empty states.
4. Tests required (unit for compose and round trip including property-style cases, reducer tests, an instrumented sheet test) and the verification commands (./gradlew :app:assembleDebug :app:testDebugUnitTest :app:lintDebug, :app:compileDebugAndroidTestKotlin, .agents/scripts/run_emulator_all_tests.sh).
5. Files to create, modify or delete, each with the reason.
6. Alternatives rejected, each with the technical reason (for example: a schema change for structured fields, rejected because schema v6 is frozen without clinical sign-off; keeping the full patient form but scrolling to the notes field, rejected because it still swaps the route).
7. Risks and what is out of scope (the new registration flow and the patient form redesign are a separate later task).
