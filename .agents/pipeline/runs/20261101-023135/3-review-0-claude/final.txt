Review of Round 4a (read-only). I read the code and tests but ran no builds or tests. I also could not run `git diff`; I only had Read, Grep and Glob, so I checked the current files and grep results.

**Hard Blockers**
1. **The profile medication list ignores the new statuses.** `ProfileScreen.kt:1968-1969` splits "Currently Taking" from "Stopped / Past" with `!it.status.equals("Stopped", ignoreCase = true)`. "Stopped" is not one of the four statuses, so Completed and Discontinued medications show under "Currently Taking". An Active record with the old non-compliant flag shows plain "Active".
   - `ProfileMedicationCard` (`ProfileScreen.kt:2054-2066`) prints raw `med.status` in a hand-coloured `Surface`. It does not use `MedicationStatusBadge` or `effectiveMedicationStatus`.
   - This breaks Q201 ("every place that shows a medication status") and Q206 ("the patient-profile display follows the chosen design"). `ProfileScreen.kt` is not in the working-tree changes, and it is not in the Q200-Q208 file list either, so it is a spec gap as well as a miss.
   - Fix: group with `isOngoingMedication(it.status, it.isNonCompliant)`, show `MedicationStatusBadge(effectiveMedicationStatus(...))`, and add `ProfileScreen.kt` to the allowed list.

**Should-fix**
2. **`IS_NON_COMPLIANT` is still alive in main code.**
   - `AncState.kt:136` has `IS_NON_COMPLIANT,` and `AncState.kt:1122` has `MedicationDraftField.IS_NON_COMPLIANT -> draft.values.copy(isNonCompliant = ...)`.
   - Only `AncStateTest.kt:443` and `:448` still use it. Q202 says to delete it if nothing else uses it.
   - It is dead for the UI, and it lets the flag drift from the status (for example Completed with the flag set).
   - Fix: delete the enum entry and the reducer branch, then change the test to send a `STATUS` event with `MEDICATION_STATUS_NON_COMPLIANT`.
3. **The print list is titled "Active Medications" but shows every medication.**
   - `PatientPrintHtmlGenerator.kt:205-210` builds rows from `patient.medications.take(...)` with no `isOngoingMedication` filter. The title is at `:1207`, and `:208` still says "No active medications…".
   - Q201 says the print "Active Medications" list uses `isOngoingMedication`, but filtering would hide Completed and Discontinued data. I'd keep showing all rows, since each has a status badge. That leaves a title that doesn't match the content, so please settle it with the owner.
4. **The Add-medication dialog is only partly checked.** I read the settings list and the dialog title and button text (`CodexSettingsSections.kt:955`, `:1056`), and those are clean. I did not read the dialog's prophylaxis switch removal at ~964; the grep shows only `isProphylaxis = false` at `:1047`, so it looks gone.

**Nits**

5a. **Print and summary status mapping.** `PatientPrintHtmlGenerator.kt:213` uses the literal `"Active"`. `ClinicalSummaryGenerator.kt:94` (`status != "Active"`), `ClinicalBadges.kt:279` and `MedicationEditor.kt:189` do the same, so the literal is repeated across several files. There's no `MEDICATION_STATUS_ACTIVE`, but the spec only asked for one constant, so I'd leave it.
