**Should-fix**
- **Spec mismatch in signatures** (`ClinicalModels.kt:24-29`, `:66`): spec Q210/Q211 give non-null `String` parameters. The code has `String?` with `= ""` defaults, and `mergeImpression` takes `String?`. This is harmless but unrequested and looser than the spec. Quote: `fun mergeImpression(existing: String?, generated: String?)`. Revert to plain `String` unless a test needs the nullable form.
- **Repeated input scan** (`ClinicalModels.kt:45-56`): the placenta and fluid branches check the vocabulary and then repeat a `when` over specific names. Fluid's `else -> null` can never run, because the vocabulary check already filtered. A tidier version drops the vocabulary check for fluid, as for fetal number. This is a small rule-duplication risk if the vocabulary ever changes, not a bug.
