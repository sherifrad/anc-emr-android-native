**Should-fix**
1. **Q119a / S99, Arabic locale fixture left in `AncWorkflowTest.kt:1078`.** `locale = Locale("ar"),` is still in the `arabicRtl()` fixture. Nothing in `values-ar` or the main sources reads Arabic strings, so it only drives an RTL layout check, which may be intended as data handling. The S99 check ("no `Locale("ar")` as a UI-string locale test") may still trip on this literal. The orchestrator should decide whether the fixture stays; I don't see a UI-string assertion tied to it.
2. **Q118, API 28-29 path is unreachable (dead code).** `BiometricAuthManager.kt:14` is `if (Build.VERSION.SDK_INT < 30) return false`, so `isBiometricAvailable` is false on 28-29 and `promptBiometric` returns at the `!isBiometricAvailable` check. The `if (SDK_INT >= 30)` branch around `setAllowedAuthenticators` therefore always runs, and the 28-29 behaviour in the spec is never exercised. I did not check whether a `canAuthenticate()` check is possible on 28-29 (`BiometricManager` is API 29+). Safe outcome, but the spec's "28-29 omits setAllowedAuthenticators" can't happen. Either say so in the report, or drop the `>= 30` guard and keep a single `< 30` gate.
3. **Q118, redundant line `BiometricAuthManager.kt:13`.** `if (Build.VERSION.SDK_INT < 28) return false` is made redundant by the `< 30` check on the next line. The same applies to the `< 28` block at the top of `promptBiometric`, since `isBiometricAvailable` already covers it. This is unrequested duplication. Lint may need the explicit version checks, so run lint before removing them.
4. **Q119e, timing decides the outcome in `discardLeftoverVisitDraft`.** It wraps a 3 s `waitUntil` in `runCatching` and treats a timeout as "no leftover draft". If a leftover draft loads in more than 3 s, it is not discarded. The later `draftContinue` wait would then see the old draft, and the Continue test would assert the wrong note. This is rare but non-deterministic.
5. **Q119e, `Thread.sleep(DRAFT_LOAD_SETTLE_MS)` before the "alert does not return" assertions.** A sleep followed by `assertDoesNotExist` is weak: it could pass before the draft loads. A deterministic signal would be better, for example waiting for a field value or the editor's loaded state. I didn't check what signals the editor exposes.

**Nit**
- `Thread.sleep(DRAFT_AUTOSAVE_WAIT_MS)` (2.5 s) before locking is required by the spec ("wait about 2 seconds"). It is a fixed wait, not a wait on a condition, so an autosave slower than 2.5 s would make the test fail.
