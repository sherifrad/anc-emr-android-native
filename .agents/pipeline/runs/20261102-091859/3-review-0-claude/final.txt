- **Should-fix:** `restoreRecord` and `evaluateRestore` never compare `command.record.patientId` with `command.patientId`. The brief asks for that generic check. Today the receipt patient, receipt recordId and `contentHash(record) == sourceDelete.deletedContentHash` bind it, because the canonical string starts with `patientId|id`. That is safe but implicit. Add one explicit `record.patientId != patientId` check. The line at `ClinicalDeleteRule.kt:27` (`if (recordContentHash != sourceHash)`) is where it would sit.
- **Should-fix:** nothing checks that `cmd.type`, `sourceDelete.type` and the record's class agree.
  - `contentHash(record)` picks the adapter from the record's class (`DeletableRecords.kt:50`). `evaluateRestore` and `insertRow` use `cmd.type`.
  - A mismatch gives a ClassCastException, which `execute` turns into `Ambiguous` (`RecordsRepository.kt:357`) rather than `INVALID_COMMAND`. No wrong row is written, because the exception fires before the DAO call and the receipt kind or fingerprint would not match anyway.
  - Fix: check `sourceDelete.type == type && adapterFor(record).type == type` in `isStructurallyValid` or `evaluateRestore`.
