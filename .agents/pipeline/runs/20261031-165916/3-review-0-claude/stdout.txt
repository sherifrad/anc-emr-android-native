- Room sets `user_version` itself, as it did for 4→5.
- Every version site is updated:
  - `RecordsDatabase.kt` has `version = 6` and `from5To6` in the migration chain.
  - `RecordsRepository.SCHEMA_VERSION` is 6. It feeds the `PRAGMA user_version` check, the metadata check at about line 100, and the seed insert.
  - `6.json` exists and `app/schemas` has 1 to 6.
- The backup envelope has its own `SCHEMA_VERSION = 3`, which is unrelated and correctly untouched.
- The existing chain is not broken, and the tests in the repo have no other hard-coded 5.
- **Should-fix:** `RecordsMigration.kt:645` `private val SCHEMA_SIX_TABLES = SCHEMA_FIVE_TABLES + "drafts"` is never used. It is dead code that produces an unused-property warning. Remove it.
- **Nit:** `validateSchemaFiveTables` and `validateSchemaFiveMetadata` are copies of the Four versions. That is the existing pattern, but it goes against "one function per rule".
- **Nit:** `private companion object` became a public `companion object` so the test can read `SCHEMA_VERSION`. It also exposes `PREGNANCY_KINDS`. Harmless, because the class is internal.

**(2) `DraftEntity` against the migration SQL**
