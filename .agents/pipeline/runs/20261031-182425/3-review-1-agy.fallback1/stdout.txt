**Review of Round 3w: not ready to merge.** I read the diff and the new files and ran no tests. Findings are grouped by severity.

**Hard Blockers**
1. **Accept can put text into the wrong record.** `DraftMapping.kt:272` `applyDraftRecord` only checks `slot != DraftSlot(record.patientId, record.screenKind)`. A slot is patient plus screen kind, but the stored `record.recordId` and `editorKind` are never compared with the open editor. A stored draft for a new visit, or for visit A, is offered when the user opens visit B, and Accept pastes it into B. `isDraftStale` compares revisions of unrelated records, so the warning won't catch this. It also affects pregnancy and probably lab, scan and medication. The prompt should only be built when the record id and editor kind match, and should be silent or worded differently otherwise.
2. **Safety guard removed from production code.** `AncState.kt` `startVisit` now reads `val patient = state.patient(...)`, `patient?.status`, and `visit == null && patient != null`. A `StartVisit` for an unknown patient with a visit id now opens an editor on default values. This looks done to make tests with `patients = emptyList()` easy. Revert it and build the test state with a patient.
3. **Arabic locale reintroduced.** `values-ar/strings.xml` (about 300 lines) is untracked and was deleted in commit 5c272ef ("100% English conversion"). Arabic-language phones would now get an Arabic UI. Owner said Arabic isn't the release language, so this needs owner confirmation, or limit Arabic to the keys the spec names.

**Should-fix**
4. **Hold race on the same slot.** `AncViewModel.kt` uses `autosaver.holdSlot` and `releaseSlot` as a set, not a counter. Open the editor (load 1 pending), close it, reopen the same slot (hold again, load 2 pending). Load 1 returns with a session mismatch and runs `else { autosaver.releaseSlot(slot) }`. That frees load 2's hold early, so the first keystroke autosaves over the stored draft before the prompt appears. Release only if the hold belongs to this session, or use a per-session token or counter.
5. **A Start event that doesn't open a new editor still triggers the hold and load.** The check is `isStartEditorEvent(event)` followed by `activeDraftSlot(current)`. The discard-dialog path in `startVisit`, `savePhase.blocksEditing()` and the archived return all leave the old editor open. The code then holds the open editor's slot and loads its own autosaved draft. A prompt can appear over the user's live text, and Accept swaps in older text. Compare the session id before and after the reduce, and only act when it changed.
6. **A failed load is silent.** `catch (_: Throwable) { null }` releases the slot. The first keystroke then overwrites the unseen stored draft. Keep the slot held, or leave the stored draft alone, when the load throws.
7. **Typing during the load window is dropped.** While the slot is held, `onStateChanged` ignores it. If no draft is found, the release doesn't re-run `onStateChanged`. So early text isn't autosaved until the next change. `DraftRecoveryFound` also doesn't check whether the form is already dirty, so Accept can erase text typed in that window.
8. **ViewModel flow has no tests.** The hold, load, release, delete and session-mismatch logic has no JVM test. Findings 4 to 6 are exactly that logic.
9. **Arabic plurals are wrong.** The plurals only define `one` and `other`. "منذ 2 دقائق", "11 دقائق" and similar read wrongly. Add `two`, `few`, `many` and `zero`, and use the singular noun for `many`. The body "لقد بدأت في الزيارة منذ …" is awkward, and "ملف المريضة" reads oddly after "في".
10. **Unrequested `requestBack` change.** The new `AncRoute.PatientList` branch, with a nine-way if-chain duplicating route rules, is not in the Round 3w spec. It changes Back behaviour on the status editor. Drop it or justify it with a test.

**Nits**
11. `reduce` is now a wrapper plus `reduceInternal`, but the inner `when` body was not re-indented, so the diff is noisy.
12. "Discard and start fresh" is a low-emphasis `TextButton` that deletes the draft with no confirmation. A mis-tap loses text for good. Consider a second confirmation or an equal-weight button.
13. `AncApp.kt` uses `age.n.toInt()` for the plural quantity. This is fine in practice.

**Your questions**
- **(1) Draft loss without Discard.** Back, outside tap, lock, process death, and opening then closing a clean editor are safe. A clean editor is not "dirty" in `closedDraftSlot`. Lock resets state without calling `closedDraftSlot`, because the vault isn't Unlocked, and `clearDrafts()` and the new AncState clear the prompt. Losses are findings 4, 6 and 7. Save-and-add-another deletes via `closedDraftSlot` as before.
- **(2) Wrong target.** The wrong-record case is finding 1. Accept generates a new `editorSessionId` (`DraftMapping.kt:274`) and clears `errors`. Image URIs keep the open editor's values (`imageUris = v.imageUris`). `saveError` and `pendingSave` are not touched by Accept, which is fine because they are blocked while a prompt is set.
- **(3) Stale rule.** `activeEditorBaseRevision` matches the `baseRevision` each branch of `draftRecordFor` stores, for all nine screens (checked on the revision field for every screen). The rule is consistent. It is meaningless for the wrong-record case in finding 1.
- **(4) Hold and release.** The held-forever path I found is finding 5 in reverse: the load coroutine always releases. A lock mid-alert is fine, since `cancelPending` clears holds and the stored draft is kept. Released too early is finding 4.
- **(5) Dialog.** `AlertDialog` is a separate window above the editor. The gate is `unlocked && !isAppLocked && needsPinSetup != true`, the same as the discard dialog. `dismissOnBackPress = false` and `dismissOnClickOutside = false` are set, and `onDismissRequest = {}`. Standard M3 buttons give a 48 dp touch target, but I didn't check focus order, TalkBack or large font on a device. There is no explicit heading or live-region semantics.
- **(6) Strings.** English grep for "memory-only" and "discarded on lock" is clean. The five named strings are rewritten, and `discard_body` ("will be lost") is correct for the Discard action. The Arabic strings are accurate apart from finding 9.
- **(7) Other.** No dead code spotted in `DraftRecovery.kt`. `activeEditorSessionId` replaced the private copy in `AncState.kt`, which is good reuse. The untracked `retry/` folder and `.agents/work` are outside the allowed paths; check them.
- **(8) Tests.** `DraftRecoveryTest` and `DraftAutosaverTest` call production code and would not compile or pass on old code. They don't cover findings 1 to 6. Instrumented tests were not run.
