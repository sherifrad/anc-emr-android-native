## Round 4a — Medication entry, four statuses, no Prophylaxis (owner 2026-11-01, D22)
Owner words: remove the Prophylaxis button; statuses exactly Active, Completed, Discontinued, Patient non-compliant; the cards and the patient-profile display follow the chosen design. Storage decision (orchestrator): the stored `isProphylaxis` field and column STAY (no migration, old backups restore unchanged); only the UI, the print badge and the summary prefix go. `isNonCompliant` stays stored and now simply mirrors the status.

One constant `MEDICATION_STATUS_NON_COMPLIANT = "Patient non-compliant"` (the literal appears once in main sources). Validation accepts all four (no other status rule changes).
Q201 (model/ClinicalModels.kt) ONE function `fun effectiveMedicationStatus(status: String, isNonCompliant: Boolean): String`: returns MEDICATION_STATUS_NON_COMPLIANT when `status == "Active" && isNonCompliant`; otherwise `status` unchanged (a Completed/Discontinued record with an old non-compliant flag keeps its status; nothing is dropped). ONE function `fun isOngoingMedication(status: String, isNonCompliant: Boolean): Boolean` = effective status is "Active" or non-compliant. Every place that decides "active medication" (WorkspaceScreen count at ~1360, ClinicalSummaryGenerator active list, print "Active Medications" list) uses it; every place that shows a medication status shows `effectiveMedicationStatus`.
Q202 (state/AncState.kt) Drafts: loading a stored medication into the draft uses `effectiveMedicationStatus`. Draft sync/recovery (DraftMapping) still round-trips both fields.
