### 2. STORAGE DESIGN
- **Table Definition**: `drafts` table inside the SQLCipher database ([`RecordsDatabase.kt`](file:///Users/sherifgamalradwan/anc-emr-android-native/app/src/main/java/com/sherifradwan/ancnative/storage/RecordsDatabase.kt)).
  ```sql
  CREATE TABLE drafts (
      patient_id TEXT NOT NULL,
      screen_kind TEXT NOT NULL,
      payload TEXT NOT NULL,
      updated_at INTEGER NOT NULL,
      base_revision INTEGER,
      editor_kind TEXT NOT NULL,
      record_id TEXT,
      PRIMARY KEY (patient_id, screen_kind)
  );
  CREATE INDEX index_drafts_patient_id ON drafts (patient_id);
  ```
  Primary key `(patient_id, screen_kind)` natively guarantees D9: "only the MOST RECENT draft per patient per screen type is kept".
- **Foreign Key / Patient Delete**: Do **NOT** declare `FOREIGN KEY(patient_id) REFERENCES patients(id)`. New patients being created have no row in `patients` yet; an FK constraint would abort draft creation for unpersisted patients. Patient deletion is nonexistent in normal clinical flow (patients are archived), but on vault restore/wipe, drafts are explicitly cleared.
- **Migration & Schema Bump**: Current `version = 5` ([`RecordsDatabase.kt#L25`](file:///Users/sherifgamalradwan/anc-emr-android-native/app/src/main/java/com/sherifradwan/ancnative/storage/RecordsDatabase.kt#L25)). Bump to `version = 6`. Add `RecordsMigration.from5To6(expectedVaultUuid)` following `from4To5` ([`RecordsMigration.kt#L290-L343`](file:///Users/sherifgamalradwan/anc-emr-android-native/app/src/main/java/com/sherifradwan/ancnative/storage/RecordsMigration.kt#L290-L343)), validating schema 5 tables, creating `drafts`, and updating `vault_metadata.schema_version = 6`. Register in `RecordsDatabase.open` ([L53](file:///Users/sherifgamalradwan/anc-emr-android-native/app/src/main/java/com/sherifradwan/ancnative/storage/RecordsDatabase.kt#L53)).
- **DAO & Repository API** ([`RecordsDao.kt`](file:///Users/sherifgamalradwan/anc-emr-android-native/app/src/main/java/com/sherifradwan/ancnative/storage/RecordsDao.kt), [`RecordsRepository.kt`](file:///Users/sherifgamalradwan/anc-emr-android-native/app/src/main/java/com/sherifradwan/ancnative/storage/RecordsRepository.kt)):

### 4. RISKS & OPEN QUESTIONS
- **Privacy & Screenshots**: Owner decision D15 (`OWNER_DECISIONS.md#L17`) intentionally removed `FLAG_SECURE`. Screen previews and screenshots can expose draft text while the app is active/backgrounded.
- **Frozen Command Idempotency**: Frozen commands ([`AncViewModel.kt#L46-L48`](file:///Users/sherifgamalradwan/anc-emr-android-native/app/src/main/java/com/sherifradwan/ancnative/state/AncViewModel.kt#L46-L48)) cache `operationUuid` and `fingerprint`. Restored drafts **must never** reuse old cached `operationUuid`s from a previous session, as retrying an abandoned operationUuid could cause `DUPLICATE_OPERATION_MISMATCH` ([`AncViewModel.kt#L704`](file:///Users/sherifgamalradwan/anc-emr-android-native/app/src/main/java/com/sherifradwan/ancnative/state/AncViewModel.kt#L704)). Restoring a draft must assign a fresh `UUID.randomUUID().toString()`.
- **Keying New Patients**: In `StartPatientEditor` ([`AncState.kt#L454`](file:///Users/sherifgamalradwan/anc-emr-android-native/app/src/main/java/com/sherifradwan/ancnative/state/AncState.kt#L454)), an unsaved new patient has no database ID. Key unsaved new patient drafts with a dedicated sentinel `patient_id = "__NEW_PATIENT__"`. This naturally ensures only the most recent new patient draft is preserved.
- **Concurrency**: An autosave job executing on the IO dispatcher might race with an immediate user "Save" submission. The repository draft write must not lock Room transactions needed by `controller.save(...)`.
- **Architectural Friction**: 9 distinct draft classes have bespoke properties. Rather than 9 separate DB tables, the single polymorphic `drafts` table with `payload TEXT` and per-draft JSON encoders avoids schema bloat.
