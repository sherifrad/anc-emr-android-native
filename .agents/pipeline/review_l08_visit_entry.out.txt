import org.json.JSONObject
import org.json.JSONTokener

const val MAX_DRAFT_PAYLOAD_BYTES = 65_536

fun encodeDraftFields(fields: Map<String, String>): String? {
    val sorted = fields.toSortedMap()
    val sb = StringBuilder()
    sb.append('{')
    var first = true
    for ((key, value) in sorted) {
        if (!first) sb.append(',')
        first = false
        sb.append(JSONObject.quote(key))
        sb.append(':')
        sb.append(JSONObject.quote(value))
    }
    sb.append('}')
    val result = sb.toString()
    val utf8Bytes = result.toByteArray(Charsets.UTF_8)
    if (utf8Bytes.size > MAX_DRAFT_PAYLOAD_BYTES) return null
    return result
}

fun decodeDraftFields(json: String): Map<String, String>? {
    val trimmed = json.trim()
    if (!trimmed.startsWith("{") || !trimmed.endsWith("}")) return null
    return try {
        val tokener = JSONTokener(trimmed)
        val obj = when (val parsed = tokener.nextValue()) {
            is JSONObject -> parsed
            else -> return null
        }
        if (tokener.more()) {
            val next = tokener.nextClean()
            if (next != 0.toChar()) return null
        }
        val result = mutableMapOf<String, String>()
        val keys = obj.keys()
        while (keys.hasNext()) {
            val key = keys.next()
            val value = obj.opt(key)
            if (value is String) {
                result[key] = value
            }
        }
        result
    } catch (_: Throwable) {
        null
    }
}

## 1. Executive Summary & Verdict

**Verdict: FAIL**

Room/persistence surface is clean (version 6, no entity or schema drift) and the pure-function predicates are internally consistent. The failure is in the **integration semantics between the new structured fields and the existing free-text `findings` / `bloodPressure` columns**: as soon as the state graph writes both, the save path silently discards what the clinician entered and can resurrect a blood pressure the clinician explicitly deleted. I verified each of these empirically by driving the real reducer + `SaveVisitCommand.prepare()` in a throwaway test (removed afterwards; working tree restored to the 4 expected modified files).

Full unit suite at HEAD+diff: **84 classes / 907 tests / 0 failures** — the green build is not evidence of the invariants, because none of the failing behaviours is exercised.

## 2. Detailed Findings

### Hard Blockers

**HB-1 — `prepare()` prefers free-text `findings`, so every structured edit on an existing visit is silently discarded** (`app/src/main/java/com/sherifradwan/ancnative/storage/SaveVisitCommand.kt:50-57`, applied at `:94`)

`findingsRaw = draft.values.findings.ifBlank { buildVisitFindings(...) }`. `DemoVisit.toDraftValues()` (`AncState.kt:1593-1610`) always seeds `findings` with the stored free text, so on **any** edit of an existing visit `findings` is non-blank and the four structured fields are dead.

Measured: visit `FH 28 cm · Oedema mild · …`; reducer set `FUNDAL_HEIGHT=30`, `OEDEMA=Marked`; `prepare()` returned `findings="FH 28 cm · Oedema mild · Movements good · Urine trace"`. The wizard shows 30/marked, the record stores 28/mild. This is the primary intended flow (edit an existing visit), so it is reachable on day one of the wizard.

**HB-2 — the BP mirror is sticky: a cleared or partial BP is resurrected or silently dropped** (`AncState.kt:1361-1373`, `SaveVisitCommand.kt:43-49`)

The mirror only ever *writes* `bloodPressure` when both components are non-blank and never clears it; `prepare()` then prefers `bloodPressure` via `ifBlank`, and falls back to composing from `systolic`/`diastolic`.

Measured:
- Edit visit with `150/95`, clinician clears systolic **and** diastolic (BP not measured this visit) → `bloodPressure` stays `150/95` → saved `150/95`. **A measurement the clinician deleted is fabricated back into the record.**
- New visit, BP field set to `150/95` then cleared → saved `150/95`. There is **no way to remove a BP** once entered.
- New visit, only systolic `185` typed → `Ready(bloodPressure=null)`: the alarming value is dropped with **no error and no flag** (neither field of the pair being blank is not treated as an error).

For a vitals column this is the wrong default: cleared must mean "not recorded", and a partial pair must be a validation error, not a silent discard.

**HB-3 — `parseVisitFindings()` can invert and destroy clinical findings, and it seeds the edit wizard** (`app/src/main/java/com/sherifradwan/ancnative/model/VisitEntryLogic.kt:175-184`, regexes `:162-165`, token stripping `:209-219`; consumed by `AncState.kt:1595`)

Legacy-phrase detection runs first and unconditionally wins over the structured token:
- `buildVisitFindings("28","Marked","Good","Negative","no edema previously")` → `Oedema marked` is parsed back as **`None`** (occupied inversion), and the free text is lost.
- Free text is absorbed into clinical values: `Urine culture sent` → `urineProtein="Culture"`; `oedema assessment` → `oedema="Assessment"`; `urine culture pending` disappears entirely (`additionalFindings=null`).
- `FH 100 cm` → `fundalHeight="10"` (regex `\d{1,2}` truncation); `FH 8 cm` accepted unvalidated.

Because `toDraftValues()` uses this parser, opening a legacy visit presents wrong structured findings to the clinician; if the free-text box is emptied (a natural action once the wizard replaces it), the misparsed values are then canonically written into the record by HB-1's `buildVisitFindings` path. Spec Oracle O5 ("lossless roundtrip") therefore does not hold.

**HB-4 — draft persistence ignores every new structured field, both directions** (`app/src/main/java/com/sherifradwan/ancnative/state/DraftMapping.kt:67-74` write, `:293-312` read)

The persisted visit draft payload is still exactly `[date, bloodPressure, weight, findings, notes, linkedUltrasoundId]` (measured). Consequences on draft recovery / process death:
- `fundalHeight`, `oedema`, `fetalMovements`, `urineProtein` are **silently lost**, and `applyDraftRecord` has no code to restore them.
- `bloodPressure` survives but `systolic`/`diastolic` do not, so the restored UI shows empty numeric BP fields while a BP is stored — and per HB-2, typing only a systolic then does nothing.

Room version/schema is untouched, so this is a payload-shape bug, not a migration issue.

### Should-fix

- **SF-1 — isolated severe systolic is not flagged** (`VisitEntryLogic.kt:9-17`, `:251-255`). `isHighBloodPressure` returns `false` unless *both* values are non-null; `detectFlaggedFindings("185","", …)` → `[]`. A one-sided 185 mmHg entry yields no alert. Treat a null partner as "unknown but flag the known high value".
- **SF-2 — no fundal-height plausibility on save or parse.** `SaveVisitCommand` validates BP and weight only; `FH 8`/`FH 999` save unchallenged. The 10..50 bound exists solely inside `estimateFundalHeightForGa`, i.e. it guards the convenience button, not the record.
- **SF-3 — `detectFlaggedFindings` logic defects** (`:267-271`): the `|| equals("Trace")` branch is dead (inner `if (contains("+"))` guards the only add), and oedema flags only `Marked`, while spec §1.6 says "marked/abnormal" — `Mild` oedema is a pre-eclampsia-relevant sign and is not flagged.
- **SF-4 — `resolveLastVisitVitals` orders by raw string date** (`:97`). Correct only for canonical ISO dates; a single non-canonical legacy row mis-orders "same as last". Same pre-existing assumption as `withCommittedVisit`, but it now feeds vitals copying.
- **SF-5 — the whole logic module is unwired.** `fillNormalVisitFindings`, `detectFlaggedFindings`, `estimateFundalHeightForGa`, `formatVisitSummary`, `resolveLastVisitVitals`, `VisitFormValues` are referenced only by tests; no UI or reducer calls them, so none of the safety invariants is enforced in the shipping app yet. Acceptable only if recorded as pending d28 wiring — it is not stated as a deferral in the spec's outcome oracles.
- **SF-6 — `formatVisitSummary` drops BP entirely when one component is missing** (`:295`), hiding partial data instead of surfacing it.

### Nits

- **N-1** `estimateFundalHeightForGa` bounds are inclusive `10..50` but 10/50 are untested; spec §1.4 prose ("1 cm/week between 20–40") contradicts the implementation (identity over 10..50).
- **N-2** `buildVisitFindings`/`parseVisitFindings` share " · " as both delimiter and joiner, and the parser also splits on ","; a comma inside free text becomes " · " (measured) — not lossless.
- **N-3** `isHighBloodPressure(raw)` conflates "not high" with "unparseable/not measured"; consider a tri-state (`BpLevel`/unknown) so future callers cannot read a parse failure as normal.
- **N-4** Test-to-spec oracle numbering diverges (spec O7 = Custom Choices, O8 = Reducer/Command; test labels O7 = summary formatter, O8 = custom choices), weakening traceability.
- **N-5** `capitalizeValue` lowercases the remainder, so free-text case is normalised (fine for presets, lossy for prose).

### Verified clean

- **Room untouched**: `RecordsDatabase` still `version = 6`, `app/schemas/**/6.json` unmodified, `VisitEntity` unchanged, no schema 7, no migration. Only 4 files modified; confirmed by `git status`.
- **`CustomChoiceList` additions are additive and safe**: keyed by `storageKey`, repository iterates `entries` with missing keys → empty, backup export/restore keyed by storage key. Dating methods are structurally outside this enum (fixed `datingMethod` draft field), so the dating-method invariance is preserved by construction, not just by the name check.
- **Reducer sync is pure, non-recursive and idempotent** (no event re-dispatch, no ordinal/`valueOf` persistence on `DraftField`) — its defect is the sticky-value semantics of HB-2, not recursion.
- **Existing validations preserved**: `DATE_REQUIRED`/`INVALID_DATE`/`DATE_IN_FUTURE`, `BLOOD_PRESSURE_INVALID` (incl. inverted), `WEIGHT_INVALID`, and `STALE_REVISION` still fire, and pre-existing `SaveVisitValidationTest` / `AncStateTest` cover them.
