### 3. Ordering
- **Is `PayloadCleanupFailed` guaranteed to land after `DeleteCommitted` on `Dispatchers.Main.immediate`? (`observed`: Yes.)**
  - In [`UndoCoordinator.beginDelete`](file:///Users/sherifgamalradwan/anc-emr-android-native/app/src/main/java/com/sherifradwan/ancnative/state/UndoCoordinator.kt#L154-L162), `reduce(AncEvent.DeleteCommitted(...))` executes synchronously to completion on `viewModelScope` (`Dispatchers.Main.immediate`) **before** `armUndo(token, restoreCmd, type = type, record = record)` is called on line 162.
  - Inside `armUndo`, `cleanupPending(previous)` launches a coroutine that switches to `ioDispatcher` (`Dispatchers.IO`) via `withContext(ioDispatcher)` and only calls `reduce(AncEvent.PayloadCleanupFailed(...))` after `finalizePayload` returns. Even with an inline dispatcher ([`UndoCoordinatorTest.kt:1086-1102`](file:///Users/sherifgamalradwan/anc-emr-android-native/app/src/test/java/com/sherifradwan/ancnative/state/UndoCoordinatorTest.kt#L1086-L1102)), `DeleteCommitted` has already been reduced before `armUndo` starts, so `DeleteCommitted`'s `deleteMessageAfterSuccessFor(patient.id)` cannot wipe the replaced record's `CLEANUP_FAILED` banner.
- **Does reducing before arming introduce any lost-offer or `updateState` clear race? (`observed`: No.)**
  - In [`AncViewModel.updateState`](file:///Users/sherifgamalradwan/anc-emr-android-native/app/src/main/java/com/sherifradwan/ancnative/state/AncViewModel.kt#L121), `if (a.undoOffer == null) undoCoordinator.clear()` only triggers when the new state has `undoOffer == null`.
  - When `DeleteCommitted` (or `UndoOffered`) is reduced on the active patient, `a.undoOffer` is the newly created non-null `offer`, so `updateState` does **not** call `undoCoordinator.clear()`, and `armUndo` on the next line cleanly cleans up any previous `pendingUndo` and arms the new `PendingUndo`.
  - Even if the clinician switched to another patient `p2` while `DeleteRecordCommand` was in flight on `p1`, `withDeleteUiConsistent()` ([`AncState.kt:389`](file:///Users/sherifgamalradwan/anc-emr-android-native/app/src/main/java/com/sherifradwan/ancnative/state/AncState.kt#L389)) sets `a.undoOffer = null` during `reduce(DeleteCommitted)` (clearing any prior `pendingUndo`), and `armUndo` then schedules the 8s expiry timer (or the next `updateState` while `undoOffer == null` calls `clear()`), which still cleans up `p1`'s deleted attachment file.
