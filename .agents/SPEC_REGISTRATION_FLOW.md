# Spec: registration step flow (new and existing patients). Owner decisions 2026-11-10. No schema change.

Flow: five steps, existing editors stay separate screens: 1 Identity (name and phone required, address, age; no date of birth), 2 Dating (DatingEditor), 3 Obstetric history (G/P/A, obstetric notes), 4 Histories (OtherHistoriesEditor, never reachable from UI today), 5 Previous pregnancies (ask "how many?" first, then existing PreviousPregnancyEditor). Segmented progress header with text "Step 2 of 5: Dating"; skipped step differs from done by text/glyph, not colour. Back / Skip (steps 2-5) / Next ("Finish" on last) at the bottom. Nothing automatic. Each step saves on its own. Incomplete patients are marked in the directory and can resume from the hub.

Design (from the read-only plan):
- New pure file state/RegistrationFlow.kt: RegistrationStep, StepStatus, RegistrationFlow, FlowEvent, reduce, deriveStepStatuses(patient), isRegistrationIncomplete(patient), suggestedPregnancyCount(g,p,a) = if g known max(g-1,0) else p+a (G counts the current pregnancy, so G = P + A + 1; ObstetricHistory.kt previousDeliverySummary only defaults G to 1 and has no count rule), clamped 0..20.
- AncState gets ONE field `registrationFlow` and ONE `AncEvent.Flow` line (AncState.kt is over 1500 lines, keep edits to a few lines). clearDrafts must not clear the flow. Flow ends on Finish, Back from step 1, Lock.
- Driver in new state/RegistrationFlowDriver.kt (chain-after-commit pattern of pendingChainedLab). Flow moves always go through Start*Editor with a fresh editorSessionId, never PendingAction.Navigate (it creates no draft). Dirty draft: existing discard dialog first.
- ui/PatientEditor.kt split into IdentityFields / ObstetricFields / RiskFields over the SAME draft and the SAME SubmitPatientProfile command; stacked as today outside the flow. Strings move to strings.xml.
- ui/components/RegistrationStepHeader.kt, RegistrationStepFooter.kt; scaffold wraps the editor routes in AncApp.kt; editors hide their own EditorActions in flow. Keep all existing testTags.
- Incomplete = archived patients never; else IDENTITY, DATING or OBSTETRIC not DONE (phone blank, no dating, G/P/A not all recorded). Steps 4 and 5 excluded (empty cannot be told from never-entered without a column). Directory card shows the text chip "Incomplete" (wraps, never truncates the name). Hub Overview shows "Continue registration" when incomplete.
- Phone required: on create and in step 1; on edit only when the stored phone is non-blank (new PatientValidationError.PHONE_REQUIRED). Level-3 path.

ORACLES (JVM): RF1 Begin gives step 1 of 5, all PENDING. RF2 Next advances and marks DONE; Next on last step with Finish ends the flow. RF3 Skip on steps 2-5 marks SKIPPED and advances; Skip on step 1 is rejected. RF4 Back moves one step without changing statuses; Back on step 1 exits. RF5 Skipped and Done render different text. RF6 deriveStepStatuses per step with one negative each (blank phone, dating null, G set but P null, all histories blank, 2 pregnancies for G=4). RF7 isRegistrationIncomplete: phone null true; phone "   " true; dating null true; G=1,P/A null true; complete patient with no histories and no pregnancies false; archived false. RF8 suggestedPregnancyCount (1,0,0)->0, (3,1,1)->2, nulls->0, over 20 clamped. RF9 profile with name+phone only is Ready; blank phone on create is rejected with PHONE_REQUIRED; edit of a legacy row with a blank stored phone is still savable; G/P/A all-or-none still rejects. RF10 StartPatientEditor(null) sets the flow; RecordCommitted and clearDrafts keep it; an empty lmpDate saves no dating.
ORACLES (androidTest, 360dp): RF11 header label fully displayed, Next reachable without scrolling. RF12 flowBack/flowSkip/flowNext displayed, enabled, >=48dp. RF13 skipped and done steps expose different text. RF14 directory card shows "Incomplete" only for the incomplete seed. RF15 hub "Continue registration" starts the first not-done step.
