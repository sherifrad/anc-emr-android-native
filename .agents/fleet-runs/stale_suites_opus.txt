## (3) The deliberate red test `attachment_deleteConfirmRemovesCardAndShowsUndoBar`

**The assertion is right, and the bug is real.**
- **Old screen:** it had `LaunchedEffect(patient.attachments)` at old `WorkspaceScreen.kt:353-355`, which set `viewingAttachment = null` once the open attachment was gone.
- **New hub:** `PatientHubScreen.kt:147` and `:270-287` have no such effect. Nothing clears `viewingAttachment` after a delete.
- **Result:** the viewer stays open on a record that no longer exists, with a working `deleteAttachmentBtn`. Tapping it again sends a second delete request for an id that isn't there.

So `missing("deleteAttachmentBtn")` fails for the right reason. The fix belongs in `PatientHubScreen`, not in the test. `attachment_cancelKeepsTheViewerOpen` still holds once that effect is restored.

## Findings

**Major**
1. **Production bug, `PatientHubScreen.kt`:** the attachment viewer stays open after its record is deleted, as described in (3).
2. **`DeleteUndoUiTest.undoBarNamesThePatient` passes for any Undo bar (older than this rewrite).** It looks for `hasText(patientA.displayName)` anywhere on screen, and the hub header always shows that name (`PatientHubHeader.kt:260/358`). It should be scoped with `and inTagged("undoBar")`.
3. **`DeleteUndoUiTest.attachment_deleteConfirmRemovesCardAndShowsUndoBar`, "Scan 1" check (also older):** it passes even if the confirm dialog shows the file name. "Scan 1" is also the title on the attachment card and in the viewer behind the dialog. It should be scoped with `inTagged("deleteConfirmDialog")`.
4. **Production, `LabReportItem.kt:369-371`:** the lab row has its own delete `IconButton` tagged `deleteLab-` instead of the shared `DeleteIconButton`. This breaks the "one canonical component" rule in AGENTS.md. It also loses the shared spoken record name, and no test checks the lab's content description. The test's `deletePrefix` comment accepts this split rather than flagging it.
5. **`PatientHubNavigation.kt`, `scrollHubTabTo` on the Overview and Plan tabs: not limited to the tab body.**
   - For those two tabs it calls `onNode(target).performScrollTo()` across the whole screen. `performScrollTo` scrolls every scrollable parent, including the `HorizontalPager`.
   - The pager keeps one neighbouring page composed (`beyondViewportPageCount = 1`). If a card moved to the next tab, the helper would swipe the pager there and `assertIsDisplayed` would still pass.
   - No current target is affected: none of them exist on Visits or Meds.
   - Fix: `target and hasAnyAncestor(hasTestTag(tab.contentTag()))`.
   - The lazy-list branch (`performScrollToNode` on the tab's own list) is properly limited. The tab-bar scroll in `openHubTab` is correct.

**Nit**
6. **`*_barDisappearsAfterAboutEightSeconds` (older than this rewrite):** they check only an upper limit of 15 s. A 1 s timer would pass. The 8 s value (`UndoCoordinator.kt:95`) has no unit test under `*Undo*` that I could find.
7. **`archivedPatientHasNoDeleteIcons` covers medication only.** Archived attachments (`canDelete` at `PatientHubScreen.kt:274`, a separate gate) and the custom lab button are not covered.
8. **`AncWorkflowTest` "P3 parity detail":** the match was loosened from exact to `substring = true`. Worth confirming why the rendered text changed.
9. **Production dead tags:** when one element carries several test tags, only the first one counts. That leaves `hubReportButton` (`PatientHubHeader.kt:230`) and the card's `workspace-`/`profile-` (`PatientDirectoryCard.kt:87-88`) unreachable. This is why the tests switched to `workspaceReportButton` and dropped `profile-`, which is correct. The dead tags should be deleted under the "no legacy baggage" rule.
