**Verdict: FIX-NEEDED.** The origin, EDD label, method and discordance rules in the spec are well pinned by pure-JVM tests, so there are no blockers. The scan-anchor helper and every `??` placement except the banner have no test, so some mutations pass silently. This is a static read only.

## Findings

**Major**
1. **`earliestScanDate` (DatingText.kt) is untested.** It is the D2 anchor in all UI and print paths.
   - Every fixture has at most one scan: `OverviewTabSectionsTest.withDating`, `ClinicalSummaryDatingTest.patient`, and the print `printDating`.
   - Nothing covers two scans, unsorted scans, a malformed scan date, or an empty list.
   - `datingSummaryOf` ("no scan, so today") is also never tested, only the lower-level `datingSummary` is, in `DatingSummaryTest.measuresAtTodayWhenThereIsNoScanDate`.
   - Add a JVM test for min-of-several, malformed-ignored and empty.
2. **The `??` marker is tested only on the banner.** The sticky bar, header, list and list-card placements have no test.
   - `gaMarkerShownWhenDiscordant` and `gaMarkerAbsentWhenNotDiscordant` call `GestationalBanner` only.
   - The `discordant =` arguments are untested in `PatientHubHeader.kt` (expanded at line 273, compact/sticky at 366) and in `Components.kt` (lines 230 and 411).
   - `projectDashboardRow().isDatingDiscordant` (list) and `eddText` are also untested. `PrintObstetricSummaryTest` asserts only `prevSummary`. `GestationalAgeBadge(discordant=true)` has no direct test either.
   - `projectDashboardRow` calls `LocalDate.now()` directly, so it needs a scan-anchored fixture or an injected date to be testable.
3. **No test for `agreedEdd` null or blank with a discordant LMP and scan EDD.**
   - `gapPatient` always sets `agreedEdd` to `lmpEdd` by default.
   - A mutation such as `val a = parseIsoDateOrNull(agreedEdd) ?: return null`, which clears the alert whenever there is no agreed EDD, passes every test.
   - D5 says only an equal agreed EDD clears it. Add the null and blank case, plus one with a malformed agreed EDD alongside a blank one.
4. **Scan before LMP is untested.** The task named this negative case.
   - With an anchor before the LMP, `datingGaDays` goes negative and falls in the ≤62 tier. The result is unpinned, so it could alert wrongly.
   - Add a test with `scan = lmp.minusDays(n)` that asserts the intended result (probably null) and no throw.
5. **`GestationalBanner` has no production caller in `app/src`.** The grep finds only the definition and the androidTest.
   - Its `earliestScanDate` parameter defaults to null, so it measures at `asOfDate` rather than the earliest scan. If it is wired in later, its `??` can disagree with the Overview alert.
   - Either wire it through `datingSummaryOf` or confirm the banner is dead code. The test proves only the banner in isolation.
6. **The Overview alert is proven only in androidTest.** That includes the exact wording, the `abs` on the gap, no button, and the nbsp.
   - `datingVariantB_*` and `datingVariantG_*` need a device or emulator.
   - The JVM suite has no test for the string-format inputs `abs(differenceDays)` and `thresholdDays` in `OverviewSections.kt`.

**Nit**
7. `FormatDmyTest.defaultLocaleDoesNotChangeDigitsOrOrder` cannot fail. `DateTimeFormatter.ofPattern("dd/MM/yyyy")` already uses ASCII digits under any default locale. The formatter is also a top-level `val`, captured once at class load. Dropping `Locale.ROOT`, or even switching to `Locale.getDefault()`, would still pass. It does no harm but proves nothing about the `Locale.ROOT` requirement.
8. **`PatientPrintHtmlEscapeTest.q93_datingSection_escapedOnce` is weaker than before.**
   - It was ≥2 `val` cells plus ≥1 `val text-rose` cell holding the escaped EDD.
   - It is now ≥2 escaped markers anywhere in the box, which are only the LMP row and the Method row.
   - With a malformed `agreedEdd`, the EDD cell shows "Not recorded", so EDD escaping and the rose emphasis are no longer asserted.
   - If no further `section-title` follows the box, `rest.length` makes the slice swallow later sections. Check that this cannot happen. The new `dating_*` tests do not cover the rose class either.
9. **`q19d` is not weakened.** The expected value moved to `08/11/2026`, consistent with U2 and U6. But the "Target Delivery Timing" row is not in the spec, so a note is needed. Its blank and malformed cases are untested; I did not check `q19`'s other cases.
10. **Ultrasound and IVF never show `US EDD`/`gap` in print or share.**
    - D5 and D7 are tested only at the `datingSummary` level.
    - `dating_methodPrintsAsLabel` and `methodSharedAsLabel` use `agreed == us` and no gap assertion.
    - An IVF print test with both an LMP and a US EDD would close this.
11. **Oracles with no test at all:** U3 "tone distinct from the high-risk banner", the warning icon, U4 colour and contrast (light and dark), and a negative test that historical GA at visits, scans and labs carries no `??`.
12. **Hardcoded English labels now live in the model layer** (`by ultrasound`, `ET`, `clinical`). The `dating_method_*` string resources were deleted. This is a design note, not a test gap.
13. **`datingDiscordanceLine`'s `abs` is covered in one direction only.** Every fixture has the US EDD later than the LMP EDD, so `differenceDays` is negative. Dropping `abs` is caught, but a reversed-sign gap with the US EDD earlier is never shown.
