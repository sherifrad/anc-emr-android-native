### Major
- **`PatientHubHeader` has no marker test.** This is `ui/patienthub/PatientHubHeader.kt`, the real workspace header. It draws the marker at line ~270 (expanded) and ~366 (compact), and nothing under `androidTest` references it.
  - `DatingGaMarkerSurfacesTest.headerCardShowsMarkerOnlyWhenDiscordant` only drives `ClinicalPatientCard` (`BEDSIDE_TOP_BAR` and `EDITOR_SUMMARY`).
  - If `gaDiscordant` were dropped or hard-coded to false in `PatientHubHeader`, every test stays green.
  - U4 names the header, so this is the largest uncovered surface.
- **The `hasGa` guard in the patient list row has no test.**
  - `PatientDirectoryMetricsRow` now shows the marker only when `hasGa && row.isDatingDiscordant`.
  - Discordance does not depend on the current GA being inside the engine's 0 to 320 day window. A discordant patient with no printable GA ("-" shown as "Pending") would otherwise get a marker with no number.
  - `listRowShowsMarkerOnlyWhenDiscordant` only uses a valid GA. Removing `hasGa` passes everything.
- **The `gaText != null` guard in `DeliveryPlanningCard` has the same gap.** Every card test uses an in-window GA.
- **The 560-day span guard has no boundary test, and the spec never defines it.**
  - `MAX_SCAN_EDD_SPAN_DAYS = 2 * FULL_TERM_DAYS` silently suppresses the alert for a scan EDD more than 560 days from the anchor.
  - Only ±999999999-year dates exercise it (`DatingSummaryTest.outOfRangeUltrasoundEddGivesNoDiscordance`).
  - Any limit from about 220 up to millions of days passes every test.
  - It suppresses a safety alert, so it needs a spec line (D6a is only about "extreme") and a boundary test at 560 and 561 days.

### Nit
- **`DatingSummaryTest.extremeLmpDateNeverThrows` and `extremeUltrasoundEddNeverThrows`** assert `s.edd == null || s.discordance == null`. That passes if `edd` is non-null and `discordance` is null for the wrong reason. It matches the D6a wording, but it is loose.
- **`DatingScanAnchorTest.scanDatedTodayIsAccepted` is a tautology.** The scan sits on `gaAlertDay` and today is also `gaAlertDay`, so the "no scan, anchor = today" fallback gives the same answer. Changing `!it.isAfter(today)` to `it.isBefore(today)` passes.
- **Tier coverage stops at the listed edges.** There is no GA below 62 (GA 0, or a negative GA from a pre-LMP anchor) and none above 196, such as GA 280. Behaviour past the last tier is unpinned.
- **`PatientPrintHtmlGeneratorTest.q19d_agreedEddMissing_notRecorded`** is unchanged by the diff, but its fixture now has all dating fields null, so it passes under any EDD implementation. The new `targetDeliveryTiming_*` tests carry the real weight.
- **`q93_datingSection_escapedOnce` is not weakened.** It is exact (2 escaped cells, EDD cell "Not recorded") rather than `>= 2`. The box delimiter moved from `section-title` to `ga-highlight`, which is fine. A malformed agreed EDD is no longer echoed raw anywhere in print; that is a behaviour change worth confirming with the owner.
- **Time dependence.**
  - `OverviewTabSectionsTest.withDating` and `ClinicalSummaryDatingTest` use a fixed scan date of 2026-08-27 against the real `LocalDate.now()`. They pass on any clock after that date and would silently change on an earlier one.
  - The related print tests pin `asOfDate`, so they are stable.
- **Header and list coverage.**
  - The sticky bar and banner are deleted, so there is nothing to cover. The removed `stickyCompactBar_displaysFullNameAndActions` test is consistent with U10.
  - No test asserts the banner is gone (there is no `GestationalBanner` caller to find).
  - The list-row marker is covered, including U12 at 360dp and 1.3x font scale for a post-term patient.
