- **The pure functions:**

- **System Back order:**
  - The order is dialog, then flow Back, then the old path, exactly as the design says.
  - A stale flow on the hub falls through to plain Back.
  - On step 1, flow Back goes to `requestBack`: a clean draft leaves, a dirty one gets the discard dialog. This is pinned by `s5_6_back_on_identity…:513`.
  - Every other flow move with a dirty draft goes through the discard dialog with `FlowMove` (`:147-153`), so no path drops edits without it.
  - While a save is running, flow Back does nothing, the same as `requestBack`.
- **ViewModel:** the removed helpers have no caller in `main`, `test`, `androidTest` or `.agents/checks`. The private `registrationNext(event)` dispatch branch (`AncViewModel.kt:192,355-366`) is intact, and `UUID` is still used.
